# 讲义体例（自学向）

这份文档约束「书城里那几本自己写的讲义」怎么写。目标只有一个：**没人陪着也能走下去**。

课堂讲稿默认有人在旁边解释——听众卡住会举手，老师会补一句。自学时这个反馈回路是断的，
所以讲稿直接搬过来会出三种毛病：① 不知道为什么要学这个；② 看不懂「显然」那一步；
③ 做错了没人告诉你错在哪。下面每一条都是针对这三种毛病设的。

## 一、每章拆成「学习单元」，每个单元固定五段

**单位不是「节」，是「一次坐下能读完的一块」。** 一节 5000 字看着不多，真读起来是两小时，
中途一断就得从头找位置；拆成 30–40 分钟的单元，读完能立刻做自测，反馈回路才闭合。

一个单元 1000–2000 字，开头一张**单元卡**（三行引用），正文五段，顺序不能乱：

| # | 段落 | 开头怎么写 | 硬性要求 |
|---|---|---|---|
| 0 | **单元卡** | `> **约 35 分钟 · 前置：1.4**`<br>`> 读完你能：① …… ② …… ③ ……` | 时长按「读 + 动手算」估；前置写单元号；三条「读完你能」必须可检验（能判断 / 能算出 / 能说清），不写「了解」「掌握」 |
| 1 | **为什么需要它** | 「先问一个问题：……」 | 用日常情境或一个具体疑问开场，**这一段禁止出现定义**；结尾要落到「所以需要这一单元的东西」 |
| 2 | **定义与结论** | 「定义 X.Y（名字）」 | 术语加粗；定理写清条件与结论，附一句「条件去掉会怎样」；**推导步骤不许跳** |
| 3 | **例题** | 「看到这个题，先找什么？」 | 固定三段：**先找什么 → 怎么做 → 为什么不用另一种做法**。第三段是从「会做一道题」到「会做一类题」的地方，不能省 |
| 4 | **出错点** | 「错误 1：……」 | 2–4 条真实错法，说清错在第几步、错因是什么；不接受「注意不要算错」这种废话 |
| 5 | **自测** | 「合上书，试着回答」 | 3–4 题，由易到难；答案放折叠块，**默认不展开** |

单元之间用 `---` 分隔。**不再写「本节术语表」** —— 术语在读的时候查不到，不如让它在定义处加粗，
真需要索引时统一进全书符号表。

折叠答案的写法（阅读器支持，DOMPurify 放行 `details`）：

```html
<details><summary>答案</summary>

这里是解答，可含 $公式$。

</details>
```

## 二、每章固定四件套

1. **章首知识地图**：回答「这一章的概念谁先谁后、谁依赖谁」。用 `mermaid` 太依赖渲染，
   改用一段缩进清单 + 一句话点出「哪一环断了后面全塌」。
2. **章首目录表**：三列 —— 单元号与标题 / 读完你能 / 分钟。**这是全章唯一的"进度尺"**，
   读者靠它决定今天读几个。
3. **章首三条阅读路线**：速通 / 标准 / 补基础，每条给单元号序列与总时长。
   不是每个人都得从头读到尾，路线让「只想过考试」和「想补基础」都能一次到位。
4. **章末「如果只记三件事」+ 综合自测**：三件事各一条；自测 8 题覆盖全章，
   至少 1 题是把两个单元接起来的综合题。

## 三、全书固定三件附属物

- **符号表**：全书的符号 → 读法 → 含义 → 首次出现位置。**每个符号第一次出现必须给读法**。
- **索引**：术语按拼音排，标注章节号。
- **前置依赖图**：哪一章需要哪一章，跨册的也要标（例如微积分的第 7 章依赖线代的特征值）。

## 四、写法禁令（逐条可查）

| 禁止 | 为什么 | 改成 |
|---|---|---|
| 「显然」「易证」「同理可得」 | 自学时这三个词等于"你自己想办法" | 把那一两步写出来，或注明"这一步展开要三行，见下方折叠" |
| 「如图可见」 | 图上没有标注就是不可见 | 图必须带坐标轴、刻度、关键点标注，正文要说"图中哪一点" |
| 「前面讲过」 | 读者可能是跳着看的 | 写成「§X.Y 讲过 ……（一句话复述结论）」 |
| 直接甩公式不解释符号 | 符号一多就变成天书 | 公式后面紧跟一行"其中 $x$ 是……，$a$ 是……" |
| 只给答案不给思路 | 学会抄，学不会想 | 例题固定三段式（见上表第 5 段） |
| 用 Unicode 数学字母（𝑥、∑ 混排） | 站内渲染会把它们拆成乱码 | 一律 `$...$` LaTeX |
| 一屏超过两个并列公式 | 眼睛没有落点 | 拆成两段，或列表化 |

## 五、「不胡编乱造」怎么保证

不是写完再校对，而是写的时候就带上可验证的东西：

1. **数值例题全部可复算**：凡是给数字的例题，答案要能用一行脚本复算。写作时同步维护
   `verify/<章>.json`（`{题, 式子, 我算的答案}`），跑 `node verify/run.mjs` 全部重算一遍。
2. **定理条件给反例**：每条定理后面附一个"去掉某个条件就不成立"的例子——这既是教学，
   也是对自己的检查（举不出反例，多半是条件没写全）。
3. **定义不循环**：术语首次出现时，只能用它前面已经定义过的东西来解释。写完用脚本扫一遍
   术语首次出现的位置，倒序引用直接报错。
4. **公式必须真渲染**：完成后把整章丢进 KaTeX 跑一遍，出现 `ParseError` 的一律修掉，
   不接受"看起来差不多"。
5. **不写没把握的断言**：拿不准的判据、历史、应用背景，宁可不写，也不要用"据说""一般认为"糊过去。

## 六、和站点结构的对应

| 讲义 | 文件 | 解析结果 |
|---|---|---|
| 书 | 一个目录（`store/<书名>/`） | 一本「书架项」 |
| 章 | 一个 `.md` 文件 | 一个可分册（左侧树的一节） |
| 节 | 文件里的 `##` | 正文里的小标题（阅读器保留） |
| 小节 | 文件里的 `###` | 正文里的小标题 |

注意：**一级标题只写一次**（章名），阅读器会把它去掉、改用文件名当标题；
`##` / `###` 会保留，所以节的划分直接靠它们。

**一级标题后面不要紧跟正文。** 站点按 `^#{1,2}\s` 切节（`parseFile`），`#` 也是一条切分线：
写在 `#` 之后、第一个 `##` 之前的那几行，会单独变成一个「只有引言」的节，
点进去第一眼看到的是一段孤零零的说明文字。要放的说明请挪到第一个 `##` 之下。

## 六·五、表格写法（手机在 360px 宽，一条都别让步）

阅读器只有 640px 版心，手机上是 330–360px。表格一旦超出，只能横向滑 —— 滑了就有内容看不见。
两条硬规矩：

1. **别超过 3 列。** 4 列在手机上几乎必然要滑；确实需要 4 列时，先问能不能把两列并成
   「条件 → 结论」一张。
2. **单元格里成串的公式要拆开写。** 行内公式是一个 `inline-block`，内部不能断行，
   它不是「几个字」，是一个**不可分割的方块**，直接决定这一列的最小宽度：

   | 写法 | 首列最小宽度 | 结果 |
   |---|---|---|
   | `$\sin x,\cos x,\tan x,\cot x,\sec x$` | ≈160px | 3 列表撑到 500px，手机上要横滑 |
   | `$\sin x$、$\cos x$、$\tan x$、$\cot x$、$\sec x$` | ≈55px | 正常折行 |

   同理：`$y=\log_a x,\ a>0,a\ne1$` 要写成 `$y=\log_a x$，$a>0,a\ne1$`。

站点侧对应地给了窄屏规则（`index.html` 的 `@media (max-width:720px)`）：
表头与首列允许折行、单元格内边距收到 `4px 6px`、表内字号 `.9em`。
但**这些只是兜底**，表本身写得宽，照样要滑。

改完正文别只看桌面：`VW=360 node scripts/probe_tables.mjs` 会把每一节里
需要横滑的表连同「差多少像素」一起打出来。
注意教材正文存在 `IndexedDB` 里是加入书架那一刻的快照，**改了 `.md` 必须先重导**，
这个探针已经内置了「清空 → 重新加入」。

## 六·六、行内公式的长度也是版式问题

行内公式不会换行。一条 400px 宽的行内公式放进 362px 的手机版心，伸出去的那 47px
会把**整个阅读器**撑出横向滚动条——读者左右滑动，看到的还是同一行字。

规矩：**估一估宽度，超过半行（≈20 个字符的 LaTeX）就不要写在句子中间**。
先写一句引子，再让公式单独成行：

```
✅  用夹逼准则证明：下面这个和当 $n\to\infty$ 时趋于 $1$。

    $$\lim_{n\to\infty}\left(\dfrac{1}{\sqrt{n^2+1}}+\cdots+\dfrac{1}{\sqrt{n^2+n}}\right)=1$$

❌  用夹逼准则证明 $\lim_{n\to\infty}\left(\dfrac{1}{\sqrt{n^2+1}}+\cdots+\dfrac{1}{\sqrt{n^2+n}}\right)=1$。
```

这条检查机器做不了（LaTeX 字符数和实际宽度不是一回事，`\forall\varepsilon\exists\delta`
十个字符能排出 300px），只能靠真浏览器量：`node scripts/probe_book1_all.mjs`
会在每一节报 `#rw 横向溢出`；要定位到具体那一行，把节序号喂给
`IDX=<节号> node scripts/probe_bisect.mjs`，它用「临时隐藏子树看宽度是否回落」
的办法一路二分到真凶。

## 六·七、单元标题与目录表：别把公式放进 `##`

单元标题会出现在**左侧课程树**里。树目是一行行短条目，一旦标题里有 `$\dfrac{\sin x}{x}$`
这种分式，那一行会被撑成三倍高，整列参差不齐。所以：

- `##` 标题里**不写 LaTeX**。「1.11 第一个重要极限：sin x / x」这样用纯文字，宁可糙一点。
- 目录表**只放两列**：`单元（时长） | 读完你能`。三列在 360px 下「分钟」表头会被拆成
  上下两个字，第一列也被压得反复折行。
- 单元卡是引用块（`>`），第一行末尾加 `<br>`，否则「时长 / 前置」和「读完你能」会并成一段。

这三条都是真机截图看出来的，不是预估 —— 版式问题只能在浏览器里发现。

## 六·八、代码围栏与跨行公式：两个不报错却很显眼的坑

**章首那张依赖关系图要用代码围栏**（三个反引号），因为树形缩进只有等宽字体才对得齐。
写的时候注意两件事：

- 围栏那两行**必须原样留在切节结果里**。站点的 `parseFile` 曾经把这两行吞掉只用来切标志，
  于是 marked 拿到的是一堆普通行，整张图被压成一段、树形符号全挤进同一行。
- 阅读器要给 `#rw pre` 单独写样式（等宽、`white-space:pre`、`overflow-x:auto`）。
  浏览器默认的 `pre` 只保证不折行，不会给你内边距和底色，也不防窄屏撑宽。

**行内公式绝不能跨行。** 下面这种写法看起来只是「窗口窄了换行」：

```markdown
误差约为 $\dfrac12\lvert f''\rvert(\Delta x)^2
=\dfrac12\cdot\dfrac14\cdot0.0004$。
```

实际后果是：`$` 与 `$` 的配对跨过了换行，下一行的中文被吞进公式，
KaTeX 报 `unicodeTextInMathMode`（站点上显示成红字），或者公式整块渲染失败。
**判据：一行里的 `$` 必须是偶数个。** 长公式改成块级 `$$…$$` 单独成行 ——
顺带也解决了它在 360px 下撑宽的问题。

## 六·九、写完一章，记得登记 `book.json`

书城卡片上的「几章 / 多少单元 / 多少公式 / 多少小时」不是手写的，是从
`store/<书名>/book.json` 的 `chapters` 算出来的。所以**加一章要动两处**：
放一个 `.md`，再在 `book.json` 的 `chapters` 里加一行。

```json
{
  "no": 3,
  "file": "第3章 微分中值定理与导数的应用.md",
  "title": "微分中值定理与导数的应用",
  "units": 14,
  "minutes": 520,
  "words": 23000,
  "formulas": 2100
}
```

- `no` 必须是章号，且与正文里 `## 3.1` 这一层的前缀一致 —— 校验脚本按它数单元。
- `file` 必须与磁盘上的文件名**一字不差**（含空格）。
- `units / words / formulas / minutes` 写实际值，`node verify/run.mjs` 会拿正文对账：
  单元数必须精确相等，公式允许 3% 浮动、字数允许 10% 浮动。

不登记会怎样：那一章不会出现在 `ORIGIN.files` 里，**「加入书架」根本不会去抓它**，
读者看到的是「书少了一章」。所以校验里那条「磁盘上每一章都登记进了 book.json」
不是形式主义，它挡的就是这个。

## 七、交付与验收：以「章」为单位

不整本一次性交，一章一交。**章不是"薄"，是"完整的一块"**——能独立读完、独立验收、独立返工。

| | 规格 |
|---|---|
| 一章 | 一个 `.md`，12–16 个学习单元，2.2–3 万字 |
| 一个单元 | 1000–2000 字，30–40 分钟，五段齐全 |
| 每章附带 | 自查报告：字数 / 单元数 / 例题数 / 自测题数 / 复算通过率 / KaTeX 报错数 |
| 验收方式 | 你先读一章，不合格只退这一章，前面几章不受牵连 |

为了不让各章各说各话，**有两份东西必须先于第一章写出来**：全书符号表、跨章前置索引。
它们不随章交付，但每写完一章都要回填——否则到第 5 章会发现前面把某个记号用反了。

## 八、交付前自检清单

- [ ] 单元数在 12–16 之间，每个单元都有单元卡（时长 / 前置 / 读完你能）
- [ ] 五段齐全，顺序没乱
- [ ] 每单元至少 1 个例题、2 条出错点、2 道自测（答案折叠）
- [ ] 章首有知识地图、目录表（带时长）、三条阅读路线；章末有「只记三件事」与综合自测
- [ ] 符号首次出现有读法；全书符号表已更新
- [ ] 数值例题复算脚本全绿
- [ ] `book.json` 的 `chapters` 已加上这一章（否则「加入书架」不会抓它）
- [ ] 每条定理都有"条件去掉会怎样"
- [ ] 全文 KaTeX 渲染无报错
- [ ] 章首依赖图用代码围栏，且阅读器有 `#rw pre` 样式（等宽、不折行、自己横向滚）
- [ ] 没有跨行的 `$…$`（每行 `$` 个数为偶数；长公式一律 `$$` 单独成行）
- [ ] 没有「显然 / 易证 / 同理可得 / 如图可见 / 前面讲过」
